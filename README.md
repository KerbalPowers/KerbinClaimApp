# Kerbin Claim Map

Interactive map for inspecting tiles and building claims, exporting the wiki nation template and a territory map.
Static site: no build step, hosted straight from GitHub Pages. Large images come from Dropbox; the two heavy
generation jobs are local Python scripts.

```
index.html, static/        the site
serve.py                   local test server (see below)
static/js/maps.config.js   <- the Dropbox links for the maps live here
static/img/                UI icons, bundled with the app
config/                    JSON the site reads (generated by tools/generate_config.py); cities.json/csv from extract_cities.py
tools/generate_config.py   builds config/ from the map images      (local, single file)
tools/tileise.py           flattens a map into one colour per tile  (local, single file)
tools/extract_cities.py    reads Cities.png into (name, x, y) data   (local, single file)
tests/core.test.js         node --test tests/core.test.js
```

## Deploy
1. Put these files in the repo root (the old `KerbinMap/` and `KerbinEcon/` folders are no longer needed).
2. Settings → Pages → *Deploy from a branch* → `main` / `(root)`.
3. Fill in `static/js/maps.config.js` (below).

## Test locally (before deploying)
```
python serve.py --open          # http://localhost:8000
```
Standard library only, nothing to install. Open it through this server rather than double-clicking `index.html`
(the browser blocks loading the JSON config from a `file://` page). The maps come from the same Dropbox links
as the deployed site, so fill in `static/js/maps.config.js` first.

## Map addresses (Dropbox)
Open **`static/js/maps.config.js`** and paste a link per image, like `MAP_URL` in the language tree. Either
the share link from Dropbox's *Copy link* button or the `dl.dropbox.com/...&st=...` form works; share links
are converted automatically. Images are loaded the way the language tree does it (`Image` with `crossOrigin='anonymous'`).

| `urls` key | file | notes |
|---|---|---|
| `Tiles` | `DataLayers/Tiles.png` | **Required.** Used for click detection. Must be in the new frame (see below). |
| `FlatMap` | `VisualLayers/FlatMap.png` | Base map: the **original 12288-wide picture, starting at the 180° line** (see below). The original is 67 MB. |
| `Climate`, `Rivers` | `VisualLayers/*.png` | Downloaded only when toggled on. Rivers takes the old Temperature slot. |
| `Language` | `DataLayers/Language.png` | The Culture layer. |

A blank link isn't an error for the overlays: the button just tells you which key to fill in. A blank `Tiles`
shows that message on the loading screen. The UI icons are not configured; they ship in `static/img/`.

* Display layers just stretch to the map, so they can be **any resolution**. Downscaled JPG/WebP copies of
  `FlatMap` and the overlays load far faster than 12288×6144 PNGs.
* `Tiles.png` must keep its **exact colours**: PNG only, and if you downscale it use nearest-neighbour. The site
  samples it at `hitScale` (0.5 = 6144×3072) and automatically retries smaller if a browser's canvas limit is hit.
* `claimedMapUrl` is the wiki's claimed-territory image. It is displayed in Claim mode; "Prevent contest" also
  needs to read its pixels, which only works if that host sends CORS headers. If not, the option greys itself out.
  Re-hosting it on Dropbox fixes that.

## Names from the language sheet
Culture, province and city names come from the same Apps Script endpoint as the language tree (`sheets` in
`static/js/maps.config.js`; a deployment id in the page `#hash` overrides it, as there). Same call: `?sheet=<tab>`.

| tab (configurable) | columns used | replaces |
|---|---|---|
| `Public` | `Family, Group, SubGroup, Language, Dialect, Hexcode` | `config/localisation/Cultures.json` |
| `Province Loc` | `Name`, `Hex` (the other columns are ignored) | `config/localisation/Provinces.json` |
| `City Loc` | `Name, X, Y` | `config/cities.json` |

If a tab can't be reached (offline, wrong tab name, timeout) the site falls back to the bundled copy in `config/` and shows
one notice, so it still works; the city tab is allowed to be missing and falls back quietly. **The `City Loc` tab name is my
guess: change `sheets.cities` if yours differs.** Continent names stay local (`Continents.json`).

## Cities
Cities are drawn from data, not from the 12288×6144 `Cities.png` (which is no longer loaded). Only points in view are drawn, at a
constant screen size, and labels that would collide are skipped. `X`/`Y` are pixels on the map image from the **top-left**, folded into one world turn (`0 ≤ X < loopWidth`).

To (re)build the list, put `Cities.png` in the `tools/` folder and run `python tools/extract_cities.py` (no arguments: it finds the image
next to itself and writes `config/cities.json` and `config/cities.csv`). Pass `--cities PATH` to use an image elsewhere.
Paste `cities.csv` (Name, X, Y, Lat, Lon) into the `City Loc` tab; the site only reads `Name`, `X`, `Y`.

## Map geometry and looping
`config/geometry.json` describes the images, and the site and the tools all read it:

| key | meaning | current |
|---|---|---|
| `width`, `height` | size of **every** layer image | 13900 × 6000 |
| `loopWidth` | pixels in one full turn of longitude; the picture repeats after this | 12288 |
| `meridianX` | column of 0° longitude | 2111 |
| `equatorY` | row of 0° latitude, counted from the top | 3000 |

`width − loopWidth` (1612 px) is the overlap strip built into the images so they can loop: the first 1612 columns are repeated at the end.
The site draws one copy of the images per world turn, `loopWidth` apart, and lets neighbouring copies **overlap by that strip**. The
layers are transparent, so where one copy of the strip is empty the other supplies the content. Wrapping your pan by one world width
means there is no edge: drag, scroll or press the arrow keys as far as you like, and clicks, claims, cities and the graticule all work
in every copy.

* **Clicking uses both copies of the strip.** The tile map's two strips are merged (the left copy wins, the right copy fills any gap), so
  a tile that is only present in one copy of the strip is still clickable.
* If a translucent layer looks denser inside the strip, both copies there are opaque-ish rather than complementary. That's the cost of
  overlapping instead of clipping; say if you want one side to win instead.
* **The flat map is the exception.** It stays the original 12288-wide picture whose left edge is the 180° line. `flatMap` in
  `geometry.json` says where it starts (`leftLongitude`, -180), and `offsetX` nudges it sideways (currently -7 px, negative = left) and, if its equator isn't the middle row (a 12288×6000 flat map, trimmed like the rest, needs nothing), `equatorY`. Its size is read from
  the file, so a downsized copy lines up too. The site places it in the new frame and repeats it for the loop (as separate images covering all the world turns on screen). Delete the `flatMap` block to treat it like the other layers.
* **Every other layer, including `Tiles.png`, must be in the 13900×6000 frame.** If `Tiles.png` has a different shape the loading screen says so
  rather than quietly mis-aligning clicks.
* The tile JSON in `config/tiles/` still holds positions in the **old** 12288×6144 frame (`tileFrame` in `geometry.json`). They are
  converted through latitude/longitude, so they don't need regenerating.
* **The latitude/longitude Grid is now generated** (`static/js/overlays.js`), not an image: lines and labels adapt to the zoom level,
  0° and the equator are highlighted. `urls.LatLong` is gone. Cities and the claim/selection highlight are drawn the same way.
* The wiki claimed-territory map is placed by its shape: old 12288×6144, full frame, or one world turn are all recognised and
  aligned. Territory PNGs are recognised the same way, so old exports can still be imported.

## Using it
**Inspect**: click a tile; Shift-click also shows its province. **Claim**: click adds, right-click removes (or use the
Add/Remove switch on touch), Shift = whole province. Export downloads `<name>.txt` (wiki template) and
`<name>_Territory.png`; Import reads a territory PNG back in (any resolution).

## Scripts
Both need `numpy` and `Pillow` (`pip install numpy pillow`, or `uv run tools/<script>.py`). `tools/kerbin_common.py` is shared by both (keep it next to them).

**Maps folder.** Set `mapsRoot` in `config/geometry.json` to the folder holding the `.pdn` files and `Layers/`; `--maps` overrides it for one run. The scripts only read the PNGs under `Layers/`
(a `.pdn` is never read; if a PNG is missing but its `.pdn` exists you get a message saying to export it). Which PNG feeds which stage is `MAP_FILES`
at the top of `tools/kerbin_common.py`:

| key | file | used for |
|---|---|---|
| Continent | `Layers/Misc/Continents.png` | continents (see shades below) |
| Provs | `Layers/Administrative/Prov Tiles.png` | provinces |
| Tiles | `Layers/Administrative/County Tiles.png` | tiles, areas |
| Language | `Layers/Demographic/Linguo-Cultural Blobs.png` | culture |
| Height | `Layers/Geologic/Height.png` | altitude (red channel) |
| Biomes | `Layers/Climate/KSP_Biomes.png` | terrain |
| Density | `Layers/Demographic/Population Density.png` | population, GDP |
| Ores | `Layers/Resource/CommonOre.png`, `RareOre.png`, `NuclearOre.png` | resources (in that order) |
| Food, Hydrates | `Layers/Resource/Food.png`, `Hydrates.png` | resources |

One file can be swapped for a run: `--map Height="Layers/Geologic/Relief.png"`.

```
python tools/generate_config.py                                                # all stages
python tools/generate_config.py --stages data claims
python tools/generate_config.py --stages build --keep-positions # rebuild, keep hand-fixed positions
python tools/tileise.py "D:/Maps/Layers/Climate/Koppen.png" [--heatmap]      # writes tools/Koppen_tiles.png
python tools/extract_cities.py
```
`tileise.py` takes one argument (the source map) and writes `<name>_tiles.png` into the `tools/` folder. It finds `County Tiles.png` by walking
up from the source to the folder containing `Layers/`, and the tile positions in `config/`.
Stages: `build` (tiles, provinces, positions, areas) -> `areas` -> `data` -> `resources` -> `claims`. New provinces/continents are appended to the localisation files as `HEX-` placeholders.

**Continent shades.** `Continents.png` has the base colours (those in `config/localisation/Continents.json`) and shades of them for subdivisions. `build`
folds each shade into its base colour by hue (shades keep their base's hue; greys/blacks go to the grey/black base) and writes every decision to
`config/localisation/ContinentShades.json` (`Shade`, `Continent`, `Pixels`, `Auto`, `Confident`). Shades the script isn't sure about are logged as `CHECK`;
fix one by editing its `Continent`, setting `"Auto": false`, and re-running `build` - it is then never overwritten. A new base continent = add its colour to `Continents.json`.
The subdivisions themselves are not kept in the tile data; the shade table is where to hang names on them later.

**Scale and area.** The one scale setting is `equatorKmPerPixel` in `config/geometry.json` (default 3769.911 km / 12288 px = 0.306796 km/px, Kerbin radius 600 km).
Circumference = that x `loopWidth`. Every layer is folded to one world turn (`loopWidth` wide) on load, so the overlap strip (`width - loopWidth` columns) never adds
area; a pixel at latitude φ has area R²·(2π/loopWidth)·(sin φ_top − sin φ_bottom), so the equator pixel is km/px × km/px and rows toward the poles shrink. Positions
and Coordinates use `meridianX`/`equatorY` from the same file. Layers must be 13900x6000 (or one 12288-wide turn); the old 12288x6144 frame is no longer accepted.

### Things worth knowing
* **`build` overwrites tile positions.** 25 tiles in the committed data have hand-corrected positions; use
  `--keep-positions` to retain them.
* **Claim weights** in the committed JSON (pop 0.16, area 12, resources ×900, no GDP term) are not the ones in the old
  `MapGen.cs` (0.08 / 10 / ×800 / GDP 0.01). The script defaults to the committed values; the C# ones are noted beside them.
* The committed `Ores.png`/`Food.png`/`Hydrates.png` no longer match the committed `LocalResources` (≈790 tiles differ), so
  re-running `resources` will change them. Apart from that, `build` and `data` reproduce the committed JSON closely (positions, areas, culture, terrain exact; population within ±1 on ~5% of tiles).
* `config/tiles` contains one duplicated tile hex (`2F75CB`); the site ignores the second copy and logs a warning.
* **Cities**: the raster marks each city with a solid **9×9** white square (not 2×2); the script uses its centre pixel. Names
  are read by matching letter bitmaps against a built-in atlas, so no OCR install is needed. Result on the current raster:
  1,140 points, 1,126 named. Of the rest: 14 squares have no text in the raster; one label (`Co?`, near the map's right
  edge) has a letter the atlas can't read; 7 pieces of text (e.g. `Montegun?`, `Kraetorea`) have no square the script could
  find and are listed under `Orphans` in `cities.json` rather than guessed. Run with `--show-unknown` for ready-to-paste atlas
  lines, or `--review-dir` for pictures of anything flagged. A new letter or ligature shows up as `?`.
* **`extract_cities.py` and the new frame**: it reads `config/geometry.json`, measures the repeat distance from the image itself and
  warns if `loopWidth` disagrees, merges the cities that appear twice in the overlap strip (keeping the copy whose label reads
  best), and computes `Lat`/`Lon` from `meridianX`/`equatorY`. An image with no overlap strip is still read as wrapping around.
* **`generate_config.py` and `tileise.py` still assume the old 12288×6144 frame** (positions and coordinates in the old frame). Use
  them with the old maps, or ask for them to be updated to the new frame before regenerating from new maps.
* **Tile areas are calculated, not read from an image.** The special equal-area `TilesArea.png` is no longer needed. Every pixel of the
  ordinary equirectangular tile map is weighted by the true area of its slice of the sphere, `R²·Δλ·(sin φ_top − sin φ_bottom)`, using the
  equator row and loop width from `geometry.json` (so pixels near the poles count for less; summed over the whole picture it gives exactly
  4πR²). In the new frame the two copies of the overlap strip are merged so each world pixel is counted once. Run
  `python tools/generate_config.py --stages areas --maps maps --config config`, then `--stages data claims`, to refresh existing data.
  * **The old areas were exactly 4/3 too large.** Compared tile by tile, the data made from the equal-area image is 1.33335× the true
    spherical area on all 6,473 tiles, at every latitude. Calculated areas are therefore 25% *smaller*, and population, GDP and claim values (which are
    built on area) drop with them. `--area-scale 1.3333333` reproduces the old numbers (median difference 0.13%, 99% of tiles within 1.2%) if you
    want to keep the balance; the default `1.0` is true area.
* **`hitScale` is 1** (full resolution): the site reads the whole 13900×6000 tile map. That is a lot of memory (roughly half a gigabyte
  while it is built); browsers that can't allocate it fall back to half size automatically.
